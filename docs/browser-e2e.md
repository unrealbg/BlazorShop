# Browser end-to-end tests

`BlazorShop.E2E` is the isolated Chromium suite for the public Storefront-to-Web checkout handoff. It starts the existing Aspire AppHost, the real API, Storefront and Blazor WebAssembly applications, and a disposable PostgreSQL 16 container. The API applies the normal EF Core migration chain before each suite.

The suite creates unique synthetic catalog and Identity rows directly in the disposable test database. It does not add test/reset endpoints, bypass authentication, mock cart or authentication HTTP responses, or submit a payment/order. Each scenario receives a fresh Playwright `BrowserContext` and independent data, and the seeded rows are removed after that scenario.

## Covered scenarios

- Home page to published category to product details, with assertions on rendered catalog content.
- Product-only cart line, quantity and server-refreshed price.
- Exact product variant selection, SKU/size/price display, quantity update, and cart-cookie persistence after reload.
- Anonymous checkout handoff to the real login page.
- UI login with a synthetic normal user and continuation to `/account/checkout` with the same variant-backed cart.

The boundary is checkout start. Stripe Checkout, webhook processing, payment completion and order creation are intentionally outside this suite.

## Local execution

Prerequisites:

- the .NET SDK pinned by `global.json`;
- Node.js 24 and `npm ci --include=dev` completed in `BlazorShop.Presentation/BlazorShop.Web`;
- a healthy Docker-compatible container runtime;
- PowerShell (`pwsh`) for the generated Playwright installer.

From the repository root:

```powershell
dotnet restore BlazorShop.E2E/BlazorShop.E2E.csproj
dotnet build BlazorShop.E2E/BlazorShop.E2E.csproj -c Release --no-restore -warnaserror
pwsh BlazorShop.E2E/bin/Release/net10.0/playwright.ps1 install --with-deps chromium
$env:BLAZORSHOP_E2E_ARTIFACTS_DIR = "$PWD/artifacts/e2e/local"
dotnet test BlazorShop.E2E/BlazorShop.E2E.csproj -c Release --no-build --no-restore --logger "trx;LogFileName=e2e.trx" --results-directory artifacts/e2e/test-results
pwsh scripts/verify-e2e-results.ps1 -Path artifacts/e2e/test-results/e2e.trx
```

The E2E configuration disables the normal named PostgreSQL data volume and pins the disposable container to `postgres:16.13-alpine3.23`. It retains the existing development HTTPS ports because the standalone WebAssembly client and Storefront-to-Web redirect use those configured origins. Run only one local AppHost/E2E instance at a time.

## CI and diagnostics

The `browser-e2e` CI job runs for pull requests targeting `master` and pushes covered by the main workflow. It installs Chromium 149.0.7827.55 and its operating-system dependencies through the `playwright.ps1` generated by Microsoft.Playwright 1.61.0. The installer temporarily sidelines and then restores an unrelated Google Chrome apt source that can make Ubuntu package metadata internally inconsistent, and has a bounded three-attempt retry for other transient mirror failures. The browser scenarios themselves run and are verified twice in succession with no test retries.

Every CI run uploads the two TRX reports and application resource logs as the `browser-e2e-<run>-<attempt>` artifact. A failed browser scenario also writes a full-page PNG and Playwright trace ZIP for that scenario. Open a trace locally with:

```powershell
pwsh BlazorShop.E2E/bin/Release/net10.0/playwright.ps1 show-trace path/to/scenario.zip
```

A missing container runtime, application startup failure, missing TRX file, zero discovered tests, non-passing result, or missing mandatory scenario fails the job. The E2E job does not use saved authentication state or production secrets; credentials and signing material are synthetic and scoped to its disposable environment.
